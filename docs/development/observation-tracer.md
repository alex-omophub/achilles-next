# Observation opportunity tracer

`generateObservationTracer()` adds three observation outputs to the existing
synthetic PostgreSQL tracer: window observed people, dense monthly observed
people and unique observed person-days. The passport and all-source person count
remain available. All 15 frozen output partitions are declared; ten remain
explicitly unsupported. The bundle stays partial, with no current-pointer
promotion, disclosure approval or durable snapshot identity.

The same [local viewer](../viewing/local-viewer.md) automatically opens either
the original count-only bundle or this observation bundle. It shows exact
values, a Recharts monthly bar chart and an exact monthly table. Counts exceeding
JavaScript's safe integer range remain exact strings and are shown in the table
without unsafe chart coordinates. Unavailable observation data retains its
reason; a valid all-source count remains visible.

## Generate → validate → view

Use the [marked fixture setup and local configuration](count-tracer.md#developer-setup).
After rebuilding changed viewer sources and installing the package:

```sh
npm run package-viewer --prefix packages/tracer
R CMD INSTALL --library=.local/R-library .
R_LIBS=.local/R-library Rscript tools/observation_tracer.R \
  tools/tracer_fixture_config.R .local/observation-bundle
node packages/contracts/tools/validate.mjs .local/observation-bundle
R_LIBS=.local/R-library Rscript -e 'AchillesNext::viewResults(".local/observation-bundle")'
```

Install the locked npm dependencies before contributor builds and create the
library/output parent directories first. Configuration and fixture credentials
stay local. An output directory must be new. Installed end-user viewing does
not invoke npm/Node/Shiny or a frontend build.

The equivalent R API accepts the same configuration as `generateCountTracer()`:

```r
environment <- new.env()
sys.source("tools/tracer_fixture_config.R", environment)
do.call(AchillesNext::generateObservationTracer,
        c(environment$config, list(outputDir = ".local/observation-bundle")))
AchillesNext::viewResults(".local/observation-bundle")
```

Only the marked tiny PostgreSQL fixtures for declared CDM 5.3/5.4/5.5 are
accepted. This is development validation of canonical fixture columns, not
institutional/clinical certification or a general OMOP analysis engine.

## Definitions and execution

The [frozen profile](../analysis/alpha-profile.md) is unchanged. All-source
people are distinct PERSON members independent of the request window. Observed
people have at least one observed day within the inclusive request window.
Monthly counts deduplicate people independently within each touched calendar
month, including clipped first and last months. Never sum monthly people to
obtain window people. Person-days count each person/date once.

The registered [observation operation](../../inst/analysis/observation-operation-v1.json)
uses a per-person running maximum of preceding interval endpoints to merge
overlaps and adjacency. A preceding single-row LAG would be incorrect for nested
intervals. The union is clipped after merging; the database sums interval
lengths instead of expanding every person/day. A bounded month calendar supplies
the dense monthly denominator. Dates use the proleptic Gregorian calendar,
years 0001–9999, without timestamp/timezone conversion.

Its internal `observed_intervals` CTE and EXISTS membership builder are reusable
by later measurement operators. EXISTS includes each physical measurement row
once despite overlapping periods, while repeated measurement IDs still denote
separate physical rows. No measurement outputs are generated by this slice.

DatabaseConnector supplies the PostgreSQL JDBC connection. The tracer owns its
read-only repeatable-read transaction and bounded aggregate result reads through
JDBC. DatabaseConnector 6.3.2's batched query cleanup ends a transaction, so that
method cannot preserve this multi-query snapshot. No person IDs or normalized
interval rows leave the database. The transaction is rolled back and the owned
connection closed on success or failure. A transaction-consistent run does not
establish an immutable source identity or authorize reuse/publication.

Unique/non-null PERSON IDs are prerequisites; failure aborts generation.
Observation table/column absence is `unavailable`, denied SELECT access is
`inaccessible`, and null/reversed/out-of-range/orphan intervals or query errors
produce `failed` observation outputs without numeric rows. Observation integrity
checks apply across that source's observation table, including out-of-window
orphans. A savepoint preserves valid PERSON results after an observation query
failure. These failures never become zero counts.

An accessible empty PERSON and valid empty observation source gives
`empty_source`. Otherwise, no observed people gives `empty_population` with
known zero counts and dense zero month rows. Each zero month has an explicit
empty state even when other months are populated. The UI explains that EHR
capture opportunity does not establish claims enrollment, continuous care or
population prevalence.

## Verification

```sh
R_LIBS=.local/R-library Rscript tests/tracer/observation.R \
  tools/tracer_fixture_config.R .local/observation-integration
for bundle in .local/observation-integration/*; do
  node packages/contracts/tools/validate.mjs "$bundle"
done
OBSERVATION_TEST_BUNDLES="$PWD/.local/observation-integration" \
TRACER_TEST_BUNDLES="$PWD/.local/tracer-integration" npm test --prefix packages/tracer
```

The integration artifact parent must be new. Fifteen canonical source/version/
window cases match the independent hand-calculated oracle. The disposable test
schema adds nested/duplicate/adjacent intervals, partial month boundaries, exact
physical-event membership, empty states, missing/denied/malformed prerequisites,
calendar extremes and wrong column types. A concurrent owner insert is invisible
to the existing runner snapshot; its transaction ID/read-only/isolation settings
are checked, and a write is refused even with INSERT privileges on the disposable
test table. The test schema is removed on exit; canonical fixtures are untouched.

Browser-provider checks consume the actual R-generated bundles, reject rehashed
semantic corruption and retain huge integer values exactly. Without the explicit
integration environment variables these cases skip. CI provisions synthetic
fixtures and enables them, while retaining dependency caching and one PR check
per branch update. Hosted success is established only after that candidate runs.
