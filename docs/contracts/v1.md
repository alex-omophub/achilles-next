# Result, provider and embed contracts v1

Contract version **1.0.0** is independent of the R package, generator, metric definitions, source releases and viewer build versions. This revision defines the [alpha profile](../analysis/alpha-profile.md)'s wire boundary. The contract package ships schemas, examples, validation utilities, TypeScript interfaces, a headless conformance harness and an experimental HTTP byte transport. A separate [count tracer](../development/count-tracer.md) now supplies partial synthetic generation, a local-file provider and a React development view. The complete analytical generator/report, Recharts visualizations and production ATLAS3 adapter remain unimplemented.

```mermaid
flowchart LR
  G[Institutional generator] --> B[Immutable validated bundle]
  B --> P[File or authenticated API provider]
  P --> V[Standalone or embedded React views]
  H[Host source and access context] --> P
  V --> E[Versioned source-scoped events]
  E --> H
```

## Validate the contract

Developer requirements: Node.js 20+ and npm. Install the pinned development dependencies and run all checks from the repository root:

```sh
npm ci --prefix packages/contracts --ignore-scripts --no-audit --no-fund
npm run check --prefix packages/contracts
```

Or validate a bundle directory directly after installing:

```sh
node packages/contracts/tools/validate.mjs tests/fixtures/contracts/complete
```

The command checks schema versions, all 15 requested outputs, typed values/states, denominator references, dense cells, selected counts, source/run/request consistency and SHA-256 integrity. The schemas use [JSON Schema 2020-12](https://json-schema.org/draft/2020-12/json-schema-validation); the Node validator registers local schemas with [Ajv's 2020 implementation](https://ajv.js.org/json-schema.html#draft-2020-12-breaking). No remote schema retrieval, type coercion, default insertion or removal of unexpected fields is enabled. Date formats are checked, including calendar validity. The source-controlled schema lock records each schema's digest.

## Bundle and publication

[bundle.schema.json](../../inst/contracts/v1/bundle.schema.json) is the manifest entry point. The [complete synthetic example](../../tests/fixtures/contracts/complete/manifest.json) contains:

- `bundle_id` and `run_id`, contract/generator/profile versions, and the exact frozen profile hash.
- A source identity record with independent snapshot, data-release, vocabulary-release and observed-schema identities. Each unknown identity carries a reason. A known snapshot records its immutable basis and assertion ID.
- The bounded alpha request and its canonical SHA-256. Canonicalization recursively sorts object keys, preserves array order and JSON-encodes scalar values as UTF-8. Request numeric fields are safe CDM integer IDs; metric values never enter this hash as floats. No Unicode normalization is performed.
- Exactly one partition entry for every required alpha output: metric ID/version, state/reason, relative path, UTF-8 byte length, SHA-256 and row count. Count/size metadata is stored as decimal integer strings.
- Local terminology metadata with its own version, vocabulary identity and asset hash.
- Disclosure policy/assertion metadata, execution window, consistency limitations and publication state.

Write result files and terminology first, validate them, then write the immutable manifest last. A producer may promote a complete pointer only after full validation; use a storage-appropriate atomic rename or compare-and-swap. `partial`/`failed` manifests have `eligible_for_current_pointer=false` and must not replace the last complete release. A complete run still declares every required output. Required unsupported/inaccessible/failed/not-requested/stale computation prevents complete-alpha publication. Policy-approved suppression is permitted only with applied disclosure policy metadata. These fields record assertions; they do not grant authorization or prove a disclosure policy was correctly applied.

The directory validator verifies declared files, rejects escaping/symlinked paths and refuses individual assets over its 10 MiB read budget. An oversized artifact must be rejected/partitioned by a later supported contract, never truncated or rounded silently. The budget is a validator resource guard, not a limit on mathematical count precision. The validator is not a data-minimization audit of unrelated files in the containing directory; serving/packaging must expose declared artifacts only.

Use source-independent identifiers for bundle/run/profile/metric versions. A new metric definition is not a new source release, and a vocabulary release is not a CDM schema version. A SQL hash or maximum event date cannot substitute for an immutable snapshot assertion. If no consistent snapshot exists, retain the execution window and limitation and disable reuse.

## Typed result rows

[result.schema.json](../../inst/contracts/v1/result.schema.json) selects a specific shape for each frozen metric ID. Unknown fields and unsupported metric/contract versions are rejected. Every document binds to source, bundle, run, request hash and metric version.

Rows contain typed dimensions, row state/reason, typed `values` and an optional denominator reference. A denominator identifies the exact metric, dimensions, field and value. The validator rejects an all-source denominator substituted for observed people even when the referenced count exists. It checks representation/unit/operator/eligibility reconciliation, selected numeric `n`, and window/month record totals. This is cross-field contract validation, not proof that a production statistical algorithm is correct.

| State | Numeric meaning |
|---|---|
| `computed` | Typed rows; a count may legitimately be `"0"`; reason is NULL |
| `empty_source` | Source is known empty; count/n is `"0"`, with reason |
| `empty_population` | Eligible population/stratum is known empty; count/n is `"0"`, with reason |
| `suppressed` | Numeric values and denominators are absent; policy reason retained |
| `unavailable`, `unsupported`, `inaccessible` | No result rows; explicit reason, never zero |
| `not_requested`, `failed`, `stale` | No result rows; explicit reason, never republished as fresh |

See the [ten standalone state examples](../../tests/fixtures/contracts/result-states.json) and [invalid mutation examples](../../tests/fixtures/contracts/invalid-cases.json). `not_requested` is representable for responses/diagnostics but cannot satisfy a fixed required alpha output in a complete bundle. A partial diagnostic artifact never claims complete-alpha semantics.

Suppressed rows inside an otherwise computed output have NULL `values` and NULL denominator. Entirely suppressed outputs have NULL `rows`. Zero-n summaries retain `n="0"` with all statistics, including sum and mean, NULL. Nonempty means retain exact `(sum,n)`; counts/decimals are strings throughout. `toSafeCountNumber` refuses integers above JavaScript's safe range rather than rounding them. Decimal values have no automatic Number conversion helper.

Availability of timing is represented within its typed metadata: `duration_ms=null`, `availability="unavailable"`, and a reason. A measured duration may be `"0"`. Capability reports can describe absent/inaccessible optional fields without becoming zero clinical counts. Required unavailable capabilities block a complete alpha bundle. Source-passport values must agree with manifest identities.

## Result providers

The [framework-neutral TypeScript interfaces](../../packages/contracts/src/index.d.mts) define:

```ts
interface ResultProvider {
  getManifest(context, { signal, requestId }): Promise<Uint8Array>;
  getResult(context, metricId, { signal, requestId }): Promise<Uint8Array>;
  getTerminology(context, { signal, requestId }): Promise<Uint8Array>;
}
```

The transport is immutable UTF-8 JSON bytes. A file provider reads declared assets; an API provider returns the same approved partition bytes through authenticated host access. Neither exposes SQL, arbitrary filenames, unrestricted filters or a query engine. The consumer verifies expected manifest/partition hashes before decoding, then validates schema and source/run/request context before rendering. Provider response serialization must preserve the published bytes; reshaping/re-serializing a partition without a new manifest is invalid.

[provider_request.schema.json](../../inst/contracts/v1/provider_request.schema.json) describes an optional JSON transport envelope: `contract_version`, `request_id`, operation, access context and exact parameters. `ReadOptions.requestId` maps to `request_id`; `AbortSignal` stays local and is not serialized. `manifest` and `terminology` have empty parameters; `result` selects a declared metric ID. The API endpoint/HTTP implementation is host-owned. Extra/cohort filters are rejected; a new analytical scope needs separately generated results.

Providers reject inaccessible/not-found/unsupported/integrity-invalid operations with classified errors, not empty success. Cancellation uses `AbortSignal`; native `AbortError` or a classified aborted error is acceptable. Providers should stop work and remove listeners when aborted. Consumers must also discard late responses from obsolete generations even if a provider cannot cancel an underlying read. These are ordinary [AbortController/AbortSignal semantics](https://nodejs.org/api/globals.html#class-abortcontroller); no host framework is required.

Authentication and refresh remain in host closures or transport configuration. Do not serialize tokens/cookies/connection strings into contexts, results, URLs, cache identities or events. The result service must enforce authorization independently of opaque access-scope IDs. Safe errors must not expose raw database queries or credentials.

The experimental `createFetchResultProvider` implements the byte transport using a host-supplied gateway base URL and an asynchronous `getHeaders(context, readOptions)` closure. It obtains current authorization for every request, forwards cancellation, disables response caching and refuses redirects. It preserves bytes and classifies 401/403/404/failure responses without exposing remote response bodies. Hash/schema/context validation remains the consumer's responsibility. The [host integration guide](../integration/atlas3.md) describes its example gateway routes and the verified, bounded ATLAS3 path.

## Identity, cache and resume

[context.schema.json](../../inst/contracts/v1/context.schema.json) requires the full `source_id`, `bundle_id`, expected `manifest_sha256`, `access_scope_id` and `authorization_epoch`. The host rotates the authorization epoch when identity/permissions change. It maps host source keys explicitly; a host's source key is not assumed to equal an analytical source ID.

After manifest validation, `inputReuseIdentity` returns NULL when snapshot/release/vocabulary/schema identity is unknown, the snapshot is not asserted immutable, execution is inconsistent, or disclosure approval is missing. Otherwise it includes all those identities, request/profile hashes, metric versions and disclosure context. This is a prerequisite key, not a durable resume implementation or proof of immutability. Recompute when unknown; verified bundle viewing is still allowed with the stated reproducibility limitation.

`viewCacheKey` adds the exact bundle/manifest selection, access scope/authorization epoch, metric and **instance ID**. No cross-instance sharing is assumed. Cache keys do not grant access. The conformance harness implements no persistent cache; a later provider/viewer must enforce these boundaries before adding one.

## Embed lifecycle and events

`MountAchilles` is an interface for a future implementation:

```ts
const instance = mountAchilles(container, {
  provider, context, view: { kind: "report", report_id: "measurements" },
  correlation_id: "host-open-1", onEvent
});
await instance.ready;
await instance.update({ context: nextContext, view, correlation_id: "host-switch-2" });
await instance.destroy();
```

The instance is returned synchronously so pending mounting can be cancelled. `ready` and `update` resolve to `applied`, `superseded` or `destroyed` with a generation; active provider/contract failures reject. The provider/callback/instance ID are fixed for the instance. Changing providers requires destroy/remount.

Updates replace the **entire** configuration supplied to `update`; contexts are never field-merged. Context/view are mandatory; omitted theme/locale reset to documented defaults (host tokens and `en`). A valid update immediately clears prior content/selections, increments generation and aborts outstanding reads. Every asynchronous boundary checks generation before committing data. An invalid update is rejected before adopting its context. Host identity changes must always supply a complete new access context or destroy the instance.

Destroy marks the instance closed immediately, aborts reads, prevents later rendering/events, clears owned content and releases owned roots/listeners/observers/workers/subscriptions. It returns one idempotent cleanup promise; repeated calls share its outcome, including cleanup errors. Never dispose a shared host-owned provider. Updates after destroy reject. Callback errors do not take ownership of renderer lifecycle. Actual DOM/root/resource cleanup and occupied-container rejection must be proved with the future browser implementation.

[event.schema.json](../../inst/contracts/v1/event.schema.json) covers `ready`, `concept_selected`, `navigation_requested`, `error` and `destroyed`. Each event includes contract/event/instance IDs, generation, correlation/origin and full source/bundle/access context. Navigation payloads identify a concept target; the host resolves its URL. Events do not take over the host router/history. Hosts route only matching current-instance/current-context events and use correlation/origin to avoid feedback loops. The destroyed event is the final event for an instance.

The headless conformance harness tests cancellation, late-response rejection, access changes, source/instance isolation and idempotent teardown. It is deliberately not an implementation of `mountAchilles` or a claim about browser rendering/CSS cleanup.

## Local terminology and optional metadata providers

[terminology.schema.json](../../inst/contracts/v1/terminology.schema.json) preserves provider ID/version, source ID and vocabulary identity. Known labels have concept/domain metadata; unknown/unavailable concepts have NULL labels and reasons. Duplicate concept IDs and mismatched source/vocabulary metadata are rejected. A numeric summary's known unit must resolve to a local `Unit`-domain concept. Missing labels do not erase recorded measurement concepts or rewrite numerical results.

`ConceptEnrichmentProvider` is a separate, optional metadata-only interface. It is disabled by default unless the host supplies and enables one. It cannot supply or mutate numeric results. Provider/version/vocabulary mismatch and outage remain explicit; local bundle terminology and results remain the default path. No remote provider, account flow or network enrichment is implemented here.

## React/Recharts and ATLAS3 integration boundary

React views can consume these decoded metric types and keep Recharts details internal. The same future view can be exposed through `MountAchilles` to a non-React host. Styles, DOM IDs, dialogs and overlays must remain inside the supplied container/portal boundary. The host owns authentication, navigation, source mapping and theme tokens.

An ATLAS3 adapter will translate its released host's mount/update/unmount lifecycle to this instance API, supply authenticated result access and map concept-navigation events. It must rotate access context on source/login/permission changes and destroy instances on unmount. A provider bridge is independent of plugin loading; an existing WebAPI is not assumed to serve this schema. A bounded native-host fixture proof is recorded in the [integration guide](../integration/atlas3.md); the production React viewer, adapter, identity-service integration and wider deployment matrix still require verification. These contracts alone do not certify an ATLAS3 installation.
